# 部署自己的纸间

本程序是单人、单进程 Node 服务端应用。每个人部署自己的实例，拥有自己的密码、AI密钥和数据目录。

## 最简单的演示

安装 Node.js 24 后，在项目目录执行 `npm start`，访问 `http://127.0.0.1:3000`。不用安装依赖，也不用填写AI密钥。先确认自己喜欢这个阅读方式。

## 对外部署需要什么

选择支持以下条件的环境：

- Node.js 24 或 Docker。
- 一个持续运行的实例，不是纯静态网页托管。
- HTTPS 域名。
- 可以挂载持久磁盘/卷，用于 `DATA_DIR`。
- 可以设置不进入Git仓库的环境变量。

云服务器、托管平台和AI调用都可能产生费用，以服务商当前说明为准。本项目没有为你开通任何付费资源。

## Node 部署

1. 上传或拉取你自己的模板仓库。
2. 配置 `HOST=0.0.0.0`、`PORT`、`APP_PASSWORD`、`PUBLIC_URL`、`DATA_DIR`。
3. 根据需要填写 `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`；默认保持 `AUTO_UPDATE_ENABLED=false`。
4. 启动命令：`node src/server.js`。
5. 将域名通过HTTPS反向代理到服务端口。代理应保留正确的Host，且 `PUBLIC_URL` 与访问地址一致。
6. 确认访问需要实例密码，收藏一则后重启程序检查数据仍在。

若显示“请使用配置的PUBLIC_URL访问”，检查部署域名与 `PUBLIC_URL` 是否相同。本机HTTP演示可以使用localhost，不应把不加密HTTP作为公网登录入口。

## Docker Compose

1. 把 `.env.example` 复制为 `.env`。
2. 设置至少12字符的独立 `APP_PASSWORD`。本机测试的 `PUBLIC_URL` 可填 `http://127.0.0.1:3000`；公网填写自己的HTTPS地址。
3. 运行：

   ```bash
   docker compose up -d --build
   ```

4. Compose 默认只把端口绑定到服务器的本机接口。通过HTTPS反向代理提供公网访问。
5. `zhijian-data` 是个人持久卷。不要随意删除卷；源码升级前先备份。

## 阅读记录与登录

本模板不包含 ChatGPT 登录集成。访问密码由每位部署者自己设置；手机和电脑用同一实例密码共享一个人的阅读记录。

若你需要“所有人共用同一网站、每个人单独账号”，需要另行增加用户注册与数据隔离，不能把本模板的单人密码当作多人系统使用。

## 定时更新

内置更新器检查配置时区的日期和小时。设置到8点时，8点之后首次在线检查会尝试运行。当日失败不会无限重试；具体错误在内容管理中查看。手动再生成是明确的人工操作，会再调用AI。

保持一个实例和一个进程，避免多个进程同时访问同一JSON数据文件。短时唤醒的免费实例可能休眠，不保证准点运行。

## 密钥

- 从你选择的AI供应商官方渠道获取API密钥。
- 使用服务端环境变量，不要把密钥写进 `public/`、README或GitHub Issue。
- 不要使用免费承诺不明确的陌生中转地址：你填写的AI服务会接收密钥与抓取的原典文本。
- 不要把AI密钥当作网页的访问密码。

## 本模板未替你完成的事项

使用者自己的AI账户、付费余额、域名和托管平台需要各自配置。提供Dockerfile不代表已经在任意云平台部署过；兼容API测试使用模拟响应，不代表每个供应商均已实测。
